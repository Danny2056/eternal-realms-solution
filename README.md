# Eternal Realms: Data Platform and Cheat Investigation

Senior Data Engineer challenge for Duskmire Studios. This repository ingests the Eternal Realms early-access
snapshot (9.65 million game events), cleans it, models it as a star schema for reporting, and runs a rule-based
cheat detector whose every finding traces back to the original events.

The original brief is in [docs/challenge-brief.md](docs/challenge-brief.md). A plain-English walkthrough of every
step, written for non-technical readers, is in [docs/how-it-works.md](docs/how-it-works.md).

## Headline findings

**Cheaters:** one coordinated group of five accounts, and nobody else.

| Account | Character | Violations | Cheats used |
|---|---|---:|---|
| acc_1017 | chr_1786 (worst offender) | 101 | Burst damage, item duplication, equip stacking, speed hack, gear above level |
| acc_1016 | chr_1785 | 77 | Burst damage, equip stacking |
| acc_1013 | chr_1782 | 48 | Burst damage, equip stacking |
| acc_1014 | chr_1783 | 48 | Burst damage, equip stacking |
| acc_1015 | chr_1784 | 48 | Burst damage, equip stacking |

* **Burst damage:** 20 hits in the same instant (the rules allow one ability every 1.5 s). They killed the final
  boss, Archon Vexmoor, in 13 seconds twice (the fastest honest kill took 176 s) and killed 18 players with one
  burst each.
* **Item duplication:** one sword bought at auction was traded to four teammates in one minute.
* All five accounts were created within 12 minutes, played only together, and stopped playing after their spree.

**Vulnerable mechanics to patch next (in priority order):**

1. **Server-side damage rate limit.** The server limits ability *uses* but accepts any number of *hits* at once.
   Enforce one hit per ability use and the 1.5 s global cooldown on damage itself.
2. **Trade ownership check.** Verify the giver still owns each item at the moment the trade completes (atomic
   check-and-transfer), so an item cannot be handed out twice.
3. **Equip slot enforcement.** Reject an equip into an occupied slot unless the unequip happens in the same
   transaction; rate-limit equip actions.
4. **Server-side movement validation.** Reject zone transitions faster than walking speed allows.

**Game anomalies (not cheating):** players never die to bosses (0 deaths in 8,137 boss fights, despite taking up
to 39 times their maximum health); 99.9% of gold created never leaves the economy; creatures deal 3 to 4 times
their stated damage in fights a player loses.

**Data quality:** seven problems found and fixed, including 47,733 duplicate deliveries, 9,615 lost events and a
shard whose clock ran 5 hours behind for the last four days. Details: [docs/data-quality-findings.md](docs/data-quality-findings.md).

## Quick start (Windows, VS Code)

Full instructions with troubleshooting: [SETUP.md](SETUP.md).

```powershell
docker compose up -d                  # start the source snapshot (read-only Postgres)
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python ingestion\extract.py           # 1. ingest into data/raw (Parquet), ~5 min, reconciles row counts
python transform\run.py               # 2. clean, check, detect cheats, build star schema, ~4 min
python reports\run_reports.py         # 3. run every report in the brief -> reports/output/*.csv
```

## Repository layout

```
ingestion/extract.py          Ingestion: Postgres snapshot -> Parquet, with row-count reconciliation
transform/run.py              Runs the SQL models in order into data/warehouse/eternal_realms.duckdb
transform/models/
  01_staging/                 Cleaning: deduplication, clock correction, JSON unpacking, value repair
  02_dq/                      Data-quality measurements and the list of lost events
  03_intermediate/            Level history, item chain of custody, damage hits with legal maximum
  04_cheats/                  Rule catalogue, 13 rules, all violations with evidence, offenders
  05_marts/                   Star schema: 6 dimensions, 10 facts
reports/sql/                  One query per report in the brief (+ cheat report and lineage)
reports/run_reports.py        Runs all report queries and saves CSVs to reports/output/
reports/export_for_powerbi.py Exports the star schema as Parquet files for Power BI (data/powerbi/)
docs/                         Findings, data model, architecture, ADRs, brief, rulebook
data/                         Generated (git-ignored): raw Parquet and the DuckDB warehouse
```
